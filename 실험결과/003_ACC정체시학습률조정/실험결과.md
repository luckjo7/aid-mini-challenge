# 실험 003 — 검증 ACC 정체 시 학습률 조정

코드 설정과 모의 검증 완료. 독립 실행 결과 CSV는 없다. 이후 실험 004의 3모델 앙상블로 확장됐다.

## 설정

- EfficientNet-B0, seed 42·43·44, 기존 학습·검증 분할과 증강을 사용한다.
- 학습률은 0.001 → 0.0003 → 0.0001 순서다.
- 각 학습률을 최소 5 epoch 적용한다. 이후부터 해당 단계의 최고 검증 ACC를 연속 5회 갱신하지 못하면 다음 학습률로 넘어간다.
- ACC가 상승하면 미개선 횟수를 0으로 초기화한다. ACC 동률은 단계 전환 판단에서 개선으로 세지 않는다.
- 학습률 전환 시 단계별 최고 ACC·단계 내 epoch·미개선 횟수를 초기화한다. 전체 최고 모델 기록은 이어간다.
- 마지막 학습률에서 같은 정체 조건을 만족하면 종료한다. 모든 단계에서 정체가 지속되면 전환은 10·20 epoch 종료 후이며 종료 시점은 30 epoch다.
- 전체 최대 50 epoch 상한이 우선 적용된다. 상한에 도달하면 현재 단계의 대기 기간이 남아 있어도 종료한다.
- 전체 최고 검증 ACC 가중치를 저장하며, ACC 동률에서는 Log Loss가 낮은 가중치를 선택한다.
- workers는 0이다.

## 저장과 비교

당시 코드는 이 폴더에 결과를 저장하도록 설정됐다. 현재 루트 baseline.ipynb는 실험 006용이다. 당시 코드 보관본은 `archive` (과거 산출물; 현재 파일 없음)다.
epoch CSV는 전체 epoch, 실제 학습률, 학습률 단계, 단계 내 epoch, 학습·검증 손실과 정확도를 매 epoch마다 즉시 기록한다.
실행별 지표와 통계도 ACC로 선택한 체크포인트 기준으로 기록한다.
comparison.csv의 기존 ACC는 실험 001에서 Log Loss로 선택한 모델의 값이다. 과거 실행의 전체 최고 ACC와 비교한 값으로 해석하지 않는다.

이전 고정 시점 학습률 코드는 [archive](../002_단계별학습률/코드/baseline.ipynb)에 보관했다.

## 앙상블 검토

시드 차이만으로도 초기 출력층·배치 순서·증강 난수가 달라진다.
증강 강도를 약·중·강으로 바꾸는 구성과 증강 종류를 달리하는 구성을 후보로 검토한다.
각 모델의 ACC와 오답 겹침, 같은 검증 이미지에서의 앙상블 ACC를 비교해 채택한다.
현재 학습 코드는 기존 증강 규칙을 사용하는 시드 3개 구성이다.
