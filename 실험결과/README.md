## 보관 구조

- 실험결과.md: 당시 목적·조건·결과·한계. 내부의 CSV·ZIP·JSON 이름은 생성 당시 기록이다.
- 코드/: 보존한 학습 노트북. 분할별 코드가 다르면 seed_N/코드/에 둔다. 같은 내용의 노트북 복사본은 하나로 합쳤다.
- checkpoints/와 ensemble.pt: 개별 최적 가중치와 결합 가중치. 전역에서 SHA-256이 같은 복사본은 하나로 합쳤으며 대체 위치는 보관파일.md에 있다.
- runs.csv·summary.csv·comparison.csv·*_metrics.csv·pairwise.csv·group_agreement.csv·components.csv: 비교·요약 지표.
- epochs/와 graphs/: epoch 기록과 학습·분석 곡선.
- 실험설정.md: JSON에서 이전한 학습 설정·완료 지표·Public 확인·가중치 출처. 기록이 있던 실험에만 존재한다.

001의 원본 model_comparison/은 해당 실험 안으로 이동했다. 번호와 실제 실행의 대응이 확정되지 않은 efficientnet_b0/와 초기 model.pt는 [초기산출물](초기산출물/README.md)에 보존한다. 공용 Places365 파일은 [사전학습가중치](사전학습가중치/README.md)에 있다.

## 최종 제출과 보관 코드

최종 제출은 [011 seed 17 T0.3 TTA](011_192크롭_패딩제거/seed_17/최종제출/README.md)이며 Public 0.0066이다. 최고 Public 0.0044를 기록한 005와 구분한다.

archive/는 없애고 001~005의 과거 노트북을 해당 실험 코드/에 합쳤다. archive의 001은 진행 막대 제거·epoch CSV 저장 변경 이후의 보관본으로, 실제 실험 001 실행 당시 코드와 완전히 같은지는 미확인이다. 005의 baseline.ipynb는 두 temperature CSV 통합 직전의 SEED=1 보관본이고, baseline_학습당시.ipynb는 기존 패키지에 있던 별도 버전이다.

노트북이 생성하는 Python 모듈은 중복 제거했다. 예외로 010의 외부 모델·추론 코드, 005 추가후보_기본TTA평균의 독립 추론 코드를 보존한다. 003은 독립 학습 결과가 없고 012는 실제 데이터 전체 학습을 실행하지 않았다.

## 다시 실행할 때

노트북 코드는 당시 상태를 보존했다. 현재 폴더에서 바로 전체 실행하는 방식으로 경로를 변경하지 않았다. 데이터·노트북을 별도 작업 폴더에 배치하는 방법과 제거한 실행 상태 파일에 따른 한계는 [루트 README](../README.md#실행-환경과-재현)를 따른다.

학습 시 기본 기록 원칙은 epoch 종료마다 CSV 즉시 저장, 배치별 진행 막대 생략, 분할 seed와 모델 seed 기록, 검증 Log Loss 기준 체크포인트 선택이다. 실험 003·004의 과거 ACC 기준 등 예외는 개별 문서를 따른다.

## 모든 학습 실험의 기본 설정

아래는 대회 당시의 기록 원칙이다. 실행 위치·보관 경로는 이번 정리로 바뀌었으며 위 안내를 따른다.

- 실제 노트북과 작업 디렉터리는 기존 프로젝트 루트를 사용한다. 실험 폴더의 코드/에는 실행에 사용한 노트북의 저장본을 복사하고 결과와 함께 보관한다.
- SEED를 바꾸면 데이터 분할과 모델 시드 네 개(SEED부터 연속), 결과 하위 폴더, 제출 파일의 분할 시드 표기를 함께 바꾼다.
- 모든 테스트에서 두 temperature 규칙을 함께 계산한다. T0.3은 기존 일치 0.3·불일치 0.7 규칙, T0.5는 전체 0.5 규칙이다.
- 제출 CSV 이름은 `submission_{SEED}_T0.3.csv`, `submission_{SEED}_T0.5.csv`로 통일한다. CSV 생성은 테스트 추론 셀 하나로 수행한다.
- 학습·검증·추론 루프에서 배치별 진행 막대를 표시하지 않는다. 학습 중에는 epoch가 끝날 때 학습·검증 지표를 한 줄로 출력한다.
- 모델·seed별로 `epochs/{모델명}_seed{시드}.csv`를 생성한다. 현재 스키마는 `epoch,learning_rate,lr_stage,stage_epoch,train_loss,train_acc,valid_loss,valid_acc`다. 매 epoch 검증이 끝나면 한 행을 기록하고 파일에 즉시 반영한다. 도중에 중단돼도 완료한 epoch의 지표는 남는다. 과거 실험은 열 구성이 다를 수 있다.
- 실험 종료 후 epoch CSV도 실행별 요약(`runs.csv`), 모델별 통계(`summary.csv`)와 함께 해당 실험 폴더에 보관한다.
- 학습률·최대 epoch·실제 실행 epoch·조기 종료 사용 여부·최소 학습 epoch·patience를 실행별 CSV에 기록한다.

## 개별 실험에 기록할 내용

| 항목 | 기록 내용 |
|---|---|
| 목적 | 무엇을 확인하려고 비교하는지 |
| 조건 | 변경한 항목, 유지한 항목, 데이터 분할, seed, 전처리, 학습 설정 |
| 환경 | 실제 실행 컴퓨터, GPU, Python·라이브러리 버전 |
| 실행별 결과 | 최저 검증 Log Loss, 해당 epoch의 정확도, 시간, 파라미터 수, 가중치·그래프 위치 |
| 전체 통계 | 반복 실행의 평균·표본 표준편차. 비교가 끝나기 전에는 최종 순위를 확정하지 않음 |
| 판단 | 채택·보류 이유와 확인하지 못한 한계 |
| 제출 기록 | 제출 CSV, 선택 모델·가중치, 제출 번호, Public 점수, CPU 추론 시간 |

실험 코드와 설정을 보관할 때는 실제 실행에 사용한 버전인지 확인한다. 완료 후 코드만 수정해서 과거 결과를 만든 코드처럼 보관하지 않는다.
